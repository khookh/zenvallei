# Deployment

## Trusted local network

Run `Setup Greenwave LAN.cmd` once. It asks for administrator approval and creates one inbound Windows Firewall rule:

- TCP port 4173;
- Private and Public Windows network profiles;
- remote address restricted to `LocalSubnet`.

Then use `Start Greenwave.cmd`. It installs from the lockfile, builds `dist`, detects the current IPv4 address and starts Vite preview on `0.0.0.0:4173`.

Remove the firewall rule when it is no longer wanted:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File scripts/configure-lan-firewall.ps1 -Action Remove
```

Useful diagnostics:

```powershell
pnpm lan:check
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File scripts/configure-lan-firewall.ps1 -Action Status
```

If port 4173 is already occupied, the launcher stops with the owning process ID. It never silently selects another address.

## Public static host

The public POC is deployed to <https://khookh.github.io/zenvallei/> by `.github/workflows/pages.yml`. Pull requests verify the application without deploying it. A verified push to `main`, or a manual run on `main`, builds and publishes `dist` through the official GitHub Pages artifact actions.

```powershell
pnpm build:pages
pnpm test:pages
```

The Pages build uses `/zenvallei/` for application, worker and data assets. Do not expose Vite preview as the public server.

The eventual host must provide:

- HTTPS;
- Brotli or gzip compression for JavaScript, JSON and GeoJSON;
- ETag or revalidation for stable data filenames;
- long immutable caching for Vite's hashed `assets` files;
- the security headers generated by `buildSecurityHeaders` in `vite.config.js`;
- a managed or self-hosted OSM-derived tile provider when traffic grows beyond this small POC.

Set `VITE_TILE_URL` and `VITE_TILE_ATTRIBUTION` at build time. `VITE_*` values are public browser configuration and must never contain a secret. Provider tokens must be explicitly designed for browser use and restricted by origin and quota.

The application works below a URL prefix. Verify a host-specific base with:

```powershell
pnpm build:subpath
```

GitHub Pages does not support the complete response-header policy generated by `buildSecurityHeaders`. The Pages build therefore includes a CSP meta policy and a referrer meta policy. `frame-ancestors`, `X-Content-Type-Options` and `Permissions-Policy` remain requirements for the next public host.

### Replacing the OSM tile service

The current OSM service is retained for modest interactive use. To change it without editing application code:

1. Choose a managed or self-hosted OSM-derived provider with browser-safe credentials.
2. Restrict the public token to `https://khookh.github.io` and set provider quotas.
3. Set GitHub repository variables `VITE_TILE_URL` and `VITE_TILE_ATTRIBUTION`.
4. Rebuild and verify the new attribution, tile origin and unavailable-tile fallback.
5. Roll back by restoring or deleting the variables and rerunning the Pages workflow.

Never store a confidential token in `VITE_*`; Vite embeds these values in public JavaScript.

## Privacy and cookies

Greenwave itself sets no cookies, browser storage, analytics or tracking identifiers. The selected language and exploration state disappear on reload.

GitHub Pages records visitor IP addresses for security. Browser requests to OpenStreetMap disclose normal request information such as the client IP, browser details, requested tile coordinates and referrer. The bilingual About panel discloses this and provides a public contact address.

## Release checklist

1. Run `pnpm install --frozen-lockfile` from a clean clone.
2. Run `pnpm verify` and `pnpm test:e2e:cross-browser`.
3. Run the full-history Gitleaks scan and confirm local credential files are ignored and untracked.
4. Review `THIRD_PARTY_DATA.md` and every visible attribution.
5. Test desktop, mobile, keyboard navigation and a failed tile connection.
6. Confirm no application cookies, analytics or browser storage are present.
7. Merge only after GitHub verification succeeds, then smoke-test all layers and both languages over HTTPS.

Rollback by reverting the faulty commit on `main`; the revert deploys the prior static state. Data migrations are not required because there is no server-side state.
